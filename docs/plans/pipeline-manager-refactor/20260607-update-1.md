补充一些原始设计思路和预期

1. InterfaceBundle被设计为了外部的统一入口，是为了匹配MaaFramework的定义。
2. Layer最初本质上是为了抽象出 一层Resource 这个概念，其实并非标准语义。因此，interface.json也是一个Layer，在最顶层。
3. 最初插件是不支持maa-tools的配置的，但是后续改为了支持。这里是一个历史遗留问题，配置的处理位置不合适。
4. 要求：在重构中注意考虑TODO#23，但不作为关键目标
5. 曾经有考虑过将lsp实现为独立进程而非嵌入插件内部，但是由于存在控制面板来具体控制行为（激活的控制器，资源等），导致发现难以设计和实现。请额外针对这个目标进行预先计划，但是不作为关键目标
6. lsp中具体提供给用户的内容（例如诊断文案，hover信息）等，目前部分存在于插件代码内部，部分存在于locale中。这里缺乏设计。按照我个人理解，其实pipeline-manager的诊断不应该含有任何文案逻辑才对
7. 目前mergeXXX等函数是缺乏设计的，只是当时简单的根据代码模式进行了一些公共函数提取，这里希望能重新梳理所需接口。
