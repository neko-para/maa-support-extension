## 包标识

- **npm 包名**: `@mse/webview`
- **类型**: VSCode 插件 Webview 前端（Vue 3）

- `@mse/extension` — 插件 host 端创建和管理 webview 实例
- 终端用户 — 通过 VSCode 界面交互

## 三个独立应用

### 1. Control Panel（控制面板）

侧边栏常驻面板，提供类 MaaPiCli 的控制界面：

- **Controller 配置**: ADB/Win32/PlayCover/Gamepad/Linux 的参数设置；Linux 的截图/输入方式由 interface 元数据的 `linux.screencap` / `linux.input` 决定（Wlr/UInput/Libei/PipeWire），面板据此展示 gamescope 实例扫描与选择、Wayland socket 路径及其合成器扫描与选择、uinput 尺寸等条件字段，并在 `pipewire_source=Portal` 时提示暂不支持
- **Resource 选择**: 切换活动的 resource bundle
- **Task 管理**: 添加/删除/配置任务选项
- **Launch**: 启动任务执行
- **Eval**: MAA 表达式求值
- **Toolkit**: 快捷工具跳转，以及管理员模式、调试模式、识别绘图落盘开关和全局快捷键目标激活；调试模式决定运行详情能否查询每次识别使用的 Raw 原图；识别绘图开关仅将带标注的 Draw 图保存到磁盘，并提示可能产生大量文件

控制面板按 Toolkit → Interface → Controller → Resource → Task → Launch/Eval 的顺序展示；先选择 Controller，再选择受其约束的 Resource。

控制器配置完整性检查会向 pipeline manager 显式注入一份浏览器占位常量表。该表只用于判断 runtime 能否构建，不参与启动；真正执行时由 extension host 使用 MaaFramework 原生常量重新构建 runtime。常量表完整枚举当前依赖的 Win32/Gamepad/Linux 常量，使依赖新增时由类型检查暴露，不修改 `globalThis.maa`。

控制面板将 interface 元数据与常规 host state 分开同步，并把两者作为浅响应式的只读快照；配置修改不会重复传输 interface。文本型任务选项会合并高频输入，避免连续写入配置并回传 state。

### 2. Crop Tool（裁剪工具）

按需创建的独立面板，布局为「顶部工具条 + 画布（底部状态栏）+ 右栏」：

- **顶部工具条**: 左侧是图像来源与保存（截图 / 上传 / 保存，无图时「截图」为主按钮）；中间是 ROI 数值，点击即复制 `[x, y, w, h]`，未框选时显示「未框选」并禁用，旁边是从剪贴板粘贴 ROI；低频动作收进「⋯」菜单（复制 `"roi"` 字段、复制外扩 50px 的 ROI、取整、收进边界、缩放到 720p、适应窗口、实际像素 1:1）；右侧是「工具 / 设置」切换和「?」快捷操作说明（快捷键表与两条典型流程）
- **画布**: `Ctrl` + 拖拽创建 ROI，拖动框或边角调整，滚轮缩放，中键拖拽平移；载入新尺寸的图像时自动适应窗口（小图不放大），同尺寸的新截图保持当前视图；底部状态栏常驻操作提示、光标图像坐标（光标在画布内时）、ROI 尺寸、图像尺寸与缩放比例
- **截图**: 通过 MaaFramework 获取屏幕截图
- **右栏**: 默认显示工具面板；工具面板由可折叠区块组成（识别测试、取色、涂绿默认展开，ROI 计算默认收起），区块标题右侧显示摘要徽标（命中结果、采样点数、绿幕「待应用 / 已应用」）；右栏显示哪个面板、展开了哪些区块、识别测试上次选中的目标都写入 `CropSettings`（`sidePanel` / `toolSections` / `testTarget`），重开面板后恢复
- **识别测试**: 一个区块统一四种目标——模板匹配、OCR、颜色匹配、节点（pipeline 节点试跑）；每个目标都有一句话说明它在哪个范围内运行（画布 ROI 或整图；节点目标使用节点自身 ROI，不使用画布 ROI），参数行以「中文名 + pipeline 字段名」展示（阈值 `threshold`、算法 `method`、忽略绿色 `green_mask`、仅识别 `only_rec`、最少像素 `count`、需连通 `connected`），运行前常驻可调；主按钮文案随目标变化（「选择模板并匹配」「选择节点并识别」），`Ctrl + Enter` 运行；运行条件不满足时按钮禁用并在提示中说明原因（无图、颜色匹配缺少颜色范围、MAA 模式下的节点试跑）
- **识别结果**: 先给一行结论（命中 / 未命中、算法、最优得分或 count/text，未命中时给出得分最高的候选，命中框可一键复制），再给识别详情树；树节点按算法展示对应字段（TemplateMatch 的 `score`、FeatureMatch / ColorMatch 的 `count`、OCR 的 `text`、`NeuralNetworkClassify` / `NeuralNetworkDetect` 的 `cls_index` / `label`），某算法没有的字段不显示占位值，Custom 的 `detail` 只在「原始 JSON」中查看（默认收起）；「在画布上标出」开关控制勾选条目的框线绘制；每个目标只显示自己最近一次的结果与失败信息，失败与未命中不再显示为空白
- **颜色匹配**: 对当前 ROI 运行 `ColorMatch`，范围直接取自取色区块的采样推荐（按外扩容差 `pickColorThreshold` 扩展，HSV 跨色相边界时拆成多区间）；方法跟随取色的 RGB/HSV/灰度选择；未采样时提供「去取色」入口
- **取色**: 点选 / 框选采样，当前像素以 HEX / RGB / HSV / 灰度可复制小块展示（点击复制并短暂显示「已复制」）；采样点以色块网格展示，点击色块移除；颜色空间、推荐算法（最小 / 最大值、均值 ± 标准差）、外扩容差可调，推荐范围 lower / upper 显示为已按容差外扩的值并可复制；「预览命中」在画布上标出命中像素；「复制 ColorMatch 片段」与「用此范围测试」（切到识别测试的颜色匹配目标并运行）
- **失败反馈**: 截图/上传/OCR/模板匹配/保存失败时返回并展示明确文案，与「未命中」区分；图像无法解码时提示并保留当前图像；用户取消（选模板文件、选节点、命名、另存为）保持静默，并保留上一次的结果与提示；保存成功后显示路径与「打开所在文件夹」（工作区外的路径用系统文件管理器打开），不自动抢焦点；空 ROI 下载会先提示，确认后才保存整图，提示在 ROI 变化后自动收起；保存文件名里的 ROI 与实际裁剪一致（取整并收敛到图像内）
- **结果归属**: 快速匹配与识别测试的结果绑定产生它的图像；识别期间或之后切换图像会丢弃旧结果，避免把旧图的识别框画到新图上
- **Custom 识别**: 非 MAA 模式下，节点使用 `Custom` 识别时会按需启动 interface 声明的 agent（节点不含 Custom 时不启动），校验 agent 是否注册了所需识别名，首次运行可能需要等待 agent 启动；相关失败（未配置 agent、未注册识别名、agent 启动/连接失败、agent 中途退出、运行中的任务占用了同名 identifier、上次识别仍在运行）以 message/告警展示；已启动的 agent 仍缺识别名时直接判为未注册，不重复启动；会话在面板全部关闭、interface/pipeline/资源变更（合并为 500ms 一次）或空闲 5 分钟后释放
- **涂绿**: 一个区块、三种生成绿幕的方式（分段切换：手动涂抹 / 自动去背景 / 圈选主体），共用一个「应用到图像」；应用会把画布上能看到的绿色（手绘笔画 + 当前方式的预览）一次烘焙成纯绿，画布上没有绿色时按钮禁用并说明原因
  - **手动涂抹**: 「开始涂抹」进入涂绿模式，画笔默认 6px，可切换橡皮擦；撤销 / 清除只在有可撤销的笔画时可用；退出涂抹后再次进入会保留已画的笔画
  - **自动去背景**: 切到该方式即自动预览、离开或收起区块即关闭；以当前 ROI（未框选时为整图）四边估计背景色，按容差做「边缘泛洪」或「全图相似色」得到背景 mask，可按像素外扩背景，只修改 ROI 内像素
  - **圈选主体**: 在画布上手画一圈圈住主体（非矩形），松开即生成绿幕预览；圈外自动判为背景、圈内用颜色模型区分主体/背景；由多个分离部件组成的主体（文字、角标）都会保留，只清理面积远小于最大部件的碎片；用于「主体 + 彩色卡片/多色背景」这类自动去背景不好处理的情况；圈选区域与预览只在该方式下显示
- **颜色预览**: 取色推荐范围可实时叠加到画布并显示命中像素数与占比，新增或删除采样点、切换颜色方法时随之刷新
- **保存模板回填**: 保存成功后在工具条下方展示路径，主操作是复制 `template` 片段；保存的模板含纯绿像素时片段才附带 `"green_mask": true`；「打开所在文件夹」显式触发，不自动抢焦点
- **涂绿与 green_mask 联动**: 「应用到图像」烘焙进图像后自动打开模板匹配的「忽略绿色」（`green_mask`），参数行旁提示「图像已涂绿」；支持「撤销应用」恢复到应用前的图像；应用后再次进入涂绿修补也保留「撤销应用」，撤销后缩略图条高亮恢复的图像
- **可视化设置**: 设置项按保存、ROI 框、视图与指示线、结果显示分组展示；运行时参数（模板阈值、取色外扩容差）不放设置页，模板阈值在识别测试参数区、外扩容差在取色区块内；结果框线颜色与字体统一使用「识别结果颜色 / 字体」；支持通过文件夹选择器自定义保存目录，未设置时按 `imageSuffix` 保存到资源 image 目录（MAA 下为 template 目录）、无资源配置时弹出另存为对话框
- **ROI 计算**: 两个 ROI 相加 / 相减（MAA 下额外给出 `rect_move`），默认收起
- **主题适配**: Canvas 背景始终跟随 VS Code 编辑器背景色，并使用主题边框界定可交互区域；不提供独立背景色配置
- **交互引导**: 无图时画布中央给出「从设备截图 / 打开本地图片」两个按钮和一句常见用法；需要图像的按钮在无图时禁用；点选/框选/涂绿/圈选是互斥模式，同一时刻只有一个生效，激活时在画布顶部显示模式横幅（含「退出 Esc」按钮），状态栏同步显示当前模式说明
- **图片历史**: 保留最近 5 张载入的图像（截图、上传、缩放、涂绿应用、外部载入），重复载入同一图像不重复记录；画布底部悬浮缩略图条（多于 1 张时显示），点击切换；切换时保留裁剪框（收敛到新图像边界内）并重置蒙版与取色状态，切换失败时保留当前图像；激活涂绿/框选/点选模式时自动隐藏
- **快捷键**: `Esc` 退出当前模式（一次一层），无激活模式时清空 ROI；焦点在输入框、下拉框或弹层内时 `Esc` 不清空 ROI（仍可退出当前模式）；`Ctrl + Enter` 运行识别测试（右栏收起时会展开识别测试区块）
- **外部识别详情**: 启动面板等通过 `setRecoDetail` 送来的节点识别详情显示在识别测试的「节点」目标下，并自动展开该区块；MAA 模式下有外部结果时同样保留「节点」目标用于查看，只禁用运行

### 3. Launch Panel（启动面板）

任务执行时的实时监控面板：

- **状态显示**: 当前任务节点、暂停/运行状态
- **控制栏**: 暂停/继续/停止按钮
- **断点管理**: 设置和管理任务断点
- **Analyzer 集成**: 通过 iframe 对接 [MaaLogAnalyzer](https://github.com/MaaXYZ/MaaLogAnalyzer)（JSON-RPC 2.0）
- **实时事件流**: 识别/动作事件的实时推送
- **详情查询**: 识别和动作详情（含缓存图像）

## 共享能力

### IPC 通信

`useIpc<ToWeb, ToHost>()` 泛型 composable：

- `send()` — 单向发送
- `call()` — request-response（通过 `seq` 匹配）
- `recv()` — 消息接收回调

自动检测 dev/prod 模式，选择 `acquireVsCodeApi()` 或 `window.parent.postMessage()`。

### 主题集成

`useTheme()` composable：

- 读取 VS Code CSS 自定义属性（`--vscode-*`）
- 动态构建 Naive UI 主题覆盖
- `MutationObserver` 监听主题变化
- 将解析后的编辑器背景色暴露为响应式状态，供 Crop Canvas 跟随主题重绘

### 国际化

Webview 使用独立的响应式 locale 系统：

- `locale.zh-cn.ts` — 简体中文字典
- `locale.en.ts` — 英文字典
- 响应式 locale 切换（`vscodeLocale` ref）

该字典只包含 Webview UI 文案，与 host/checker 使用的 `@nekosu/maa-locale` 没有相同 key；独立边界及重新评估条件参见 [locale-system.md](../../extra/locale-system.md)。控制面板的 Linux 控制器相关文案使用 `maa.control.*` 前缀（扫描/选择 gamescope 实例与 Wayland 合成器、提示 Portal 模式未支持等）。

## 抽象边界

- 所有 Webview 代码在浏览器沙箱中运行
- 不直接访问 Node.js API
- 通过 `@nekosu/maa-types` 的类型协议与 host 通信
- 使用 `Buffer` polyfill 兼容引用的节点类型
